- [x] Fixed in round 2 (`cmd_gate` compares the tree before the busy branch; `test_a_busy_answer_that_changed_the_tree_is_a_failed_attempt`). security: plugins/factory/scripts/factory.py:3934: `cmd_gate` returns through `_gate_busy()` (`if busy: return _gate_busy(...)`) before it works out `changed` from `before`/`after`. So a busy run that changes the worktree is never seen. A gate's "Tree: changed → FAIL" rule exists to catch a check, running code the builder wrote, that rewrites the change it is judging. On a host that sets `[park] exit`, that code can now edit files, exit with the park code (for example `os._exit(75)` from a test), and leave the edit behind. The next attempt's `before` already holds the edit, so it reads `Tree: unchanged` and goes green, with `Build:` still the hash of the snapshot taken before the edit. Later rounds' reviewers read only `reworked`, worked out from those snapshots, so an edit on a path the rework didn't touch never reaches a reviewer. On `--land`, the gate goes green on a worktree that differs from the commit that lands. Fix: compute `changed` before the busy branch, and treat a busy answer as busy only when nothing changed (`busy = None if changed else busy`). A busy run that changed the tree then becomes a normal `FAIL` attempt with `Tree: changed: …`. Add a test where a check edits a tracked file and exits with `[park] exit`, asserting a FAIL attempt is written and no `runs/parked.md`.
