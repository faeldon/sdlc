
Resolved:
- **Does `commands.build` run on every build round, or only once at the landing's tip?** Once, at the landing train's tip, after the tip's gate is green. That includes a train of one that never moved, which has no gate due. A red build stops the train and isn't bisected. This is the bug's own expected behaviour ("at least once before landing (the train's tip gate)"); a build in every round would pay the slow gate each round, which ship never does. The choice is yours to overturn. A build in every round would show a red build to the builder while it can still fix it, at the cost of one slow run per round. Bisecting a red build would eject the change at fault instead of stopping, at ⌈log₂ n⌉ more slow runs.
- **Is the hash recorded at `train --begin` the text the person approved?** Yes. `land-check` shows the checks from `sdlc.py preflight`'s `checks` part, and between the question and `--begin` the land skill runs only `factory.py accept` and `cases`. Neither can leave `checks.md` changed: a check that changes the tree fails (`left`).

Left for the person:
- **The read-only allow-list (open question 2).** The spec proposes: `grep`, `cat`, `head`, `tail`, `wc`, `test`, `[`, `true` and `false`, plus `git log`, `git show` and `git diff`, without `--output`, `--ext-diff` or `--textconv` and with no option before the subcommand. It refuses redirection, `$`, backticks, `\`, subshells, brace groups, background jobs and unquoted globs, and any path outside the checkout (absolute, `~`, `..`, or a symlink out). Unlike the idea, it leaves `awk` out, because its program can call `system()` and write with `>`. Adding `awk` (and `sed`) with their dangerous forms refused would clear more checks unattended, but it means a parser for their languages and more ways to get it wrong. Leaving them out means a changed check that uses them stops for you.
- **The policy edit in Contracts touched.** The intent's own wording, "behind the person's yes for that exact command", is narrower than its Outcome. A changed check also runs on the approver's HARMLESS plus the read-only list. Approving this spec approves the `AGENTS.md` edit that says so.
- **Secrets inside the checkout.** A read-only command like `cat .env` passes the list, and its output lands in the committed `build/land-accept.md`. Only the approver guards against it. If that isn't enough, R5 could also refuse dotfiles and any path the repo's `.gitignore` ignores. That would stop a few legitimate checks.
