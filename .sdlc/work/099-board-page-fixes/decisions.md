# Decisions

- [x] D1 (builder round 1, default): Label on the chip: visible or accessible-only (the intent's open question)? Options: visible text; `aria-label` or a visually hidden label only. Going ahead with visible text `verifier: kept N · dropped M`. Only visible text reaches sighted keyboard and touch users, who are part of the bug. Browsers also often ignore an `aria-label` on a plain span. The chip only gets wider. → decided: visible text, `verifier: kept N · dropped M`
- [x] D2 (builder round 1, default): Phone order by CSS `order` alone, as the Approach says, or by also reordering the page so Tab follows what's on screen? Going ahead with CSS alone, with the reordering logged in `notes.md` as a follow-up. → decided: superseded by D3 and D4: round 2 orders the columns in the page (`columnOrder()`), not by CSS alone
- [x] D3 (code round 1, default): Phone order is CSS-only, so keyboard and screen-reader order still puts Needs you last. Intent O6 says the board "reads the same on a phone, by keyboard and with a screen reader", and that is not true yet. The build's D2 defaults to CSS alone, with the fix logged in `notes.md`. My recommendation is to build the columns in phone order in `render()`, from a `matchMedia("(max-width: 760px)")` check that re-renders on `change`. That keeps DOM order, Tab order and the visual order the same, and it is a small change in the same file. The person should pick between that and CSS-only for this change, since it adds a little JS, and `notes.md` should carry the decision either way. → decided: order the columns in the page with `matchMedia`, as round 2 built
- [x] D4 (ui round 1, default): The phone reorder is visual only. `.col.needs-you { order: -1 }` (board.html:47) moves Needs you above Plan, but the DOM and the Tab order stay in stage order, so a keyboard or screen-reader user at 390px reaches Plan's cards first, then Needs you last. Outcome O6 says the board "reads the same … by keyboard and with a screen reader", which this conflicts with. Options: (a) at `max-width: 760px`, have the script move the `needs-you` section to the front of `#board` (via `matchMedia`, re-applied on change), so the DOM, focus and speech order match the look; or (b) keep CSS-only and record in the change that visual and focus order differ at phone width. Recommendation: (a), since it keeps the outcome true and is about 5 lines of script. → decided: order the columns in the page with `matchMedia`, as round 2 built
