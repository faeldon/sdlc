# Decisions

- [x] D1 (builder round 1, default): Should R8's "left out of every median" apply per measure? Options: drop unrecorded changes from every median (the spec's literal wording); or drop them only from figures they can't supply. Going ahead with the second: an unrecorded change is in no tool-call figure, but its comment lines (from git) and its `out` tokens (on older `Close` commits too) still count. Recommend this because the literal reading leaves even the git-only comment view (which the intent's constraint promises when `metrics.transcripts` is off) empty until three changes close after this one. → decided: the assumed default, confirmed when landing
- [x] D2 (builder round 1, default): Should each change's own `spend` rows print only with `--metrics`? Options: always; only with `--metrics`. Going ahead with only `--metrics`, as `changes[].metrics` already works. Recommend this because of the contract that a change's own numbers print only with `--metrics`. The summary (recorded/unrecorded counts, `why`, medians, outliers, tools) always prints, so the spec's Verification step `retro | jq .spend` shows the counts and reasons rather than per-change rows unless run with `--metrics`. → decided: the assumed default, confirmed when landing
- [x] D3 (builder round 1, default): Where do added code lines come from? Options: `rec["by_kind"]` (numstat); or the same `-U0` diff the comments come from, filtered to code by `_kind()`. Going ahead with the diff: one git call gives both numbers. A suffix with no marker counts in `code_added` but not in the comment share's base (`comment_base`). → decided: the assumed default, confirmed when landing
