
- **Resolved: how the board identifies its repo.** By a hash of the main checkout's resolved path (`repo_id`), not the path itself. It compares the same, keeps a home path out of `state.json`, and is the same from every worktree of the repo, because `main_root()` is (`scripts/sdlc.py:793`).
- **Resolved: whether reading the lock belongs in `factory_records.py`.** No. That module is pure and parses only change-folder files (its docstring). The run lock is a lock in the git common dir, like the gate slots, whose copies stay outside it. The copy goes in `board.py`, so a board that is already running needs no restart (it keeps the old `sdlc.py` in memory).
- **Left for you: how the run lock is read.** The draft uses a non-blocking try, which the factory's own `train_running()` uses too. It takes a free lock for the span of two syscalls and never touches a held one. With a train under way and a board open, a `train --run`, `--begin`, `--eject` or `--stop` started at that exact instant is refused once and works on a rerun. Your intent's constraint "must not take it" rules this out as written. The other choice is a pid the loop writes into the lock file. It never takes the lock, but it means a `landing.py` change, Windows process checks through `ctypes`, and false "live" readings when a pid is reused. Say which, and R7–R10 and *Contracts touched* are adjusted to match.
