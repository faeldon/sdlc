
**Open questions resolved**
- **Drop the shortcut outright, or keep it when the trees provably match?** Drop it. The intent's Outcome already asks for the committed, stacked commit to be gated "like a longer train". The code shows why the proof is unsafe: `build_hash()` covers the worktree, not what git tracks, which is the gap that let the untracked file through (see Alternatives rejected).
- **Does `factory.py fresh` need to invalidate the round's gate for the landing?** No, not once this lands. The landing no longer reads a round's gate as standing in for its own, so how the base moved before `--begin` stops mattering. R1's second case pins it.

**Left for the person**
- **Should the build round's gate count untracked files as tracked (`git add -N` before `[commands] check`)?** Yes would catch this kind of failure a round earlier, where the builder can still fix it. The cost is changing the worktree's index during a gate that must leave the tree as it found it, and touching every build round. No leaves the landing gate as the one backstop, at the cost of an ejection late in the run instead of a red round. This spec doesn't do it either way. If you want it, it is a separate seed.
- **Should a landing whose change carries `unreviewed=N` also run a landing review?** Yes costs one more agent round per such landing, and is a change to `land_signals()` and the review step. No keeps `unreviewed=N` as a signal that only makes the WAIT the person's, which it already does. This spec doesn't do it either.
